  3.  sealed trait Jwk extends AnyRef

    A public JSON Web Key as defined by RFC 7517.

    A public JSON Web Key as defined by RFC 7517.

    Only the public parameters of RSA, EC and OKP keys are modelled. Private members such as d, p, q, dp, dq, qi or oth are ignored: they are never read when parsing and never written by toJson.

    The certificate members x5c, x5t, x5t#S256 and x5u are ignored too: no certificate chain is read, validated or checked against the key, and they are never written by toJson.

    Keys are immutable values. Use the companion factories to construct them, named accessors to inspect them and withKeyId, withUse, withAlgorithm or withKeyOperations to update their metadata. They deliberately do not expose case-class copy, extractors or Product APIs, so that the model can evolve without changing those public signatures.

  5.  final class JwkThumbprint extends AnyRef

    A JWK thumbprint as defined by RFC 7638.

    A JWK thumbprint as defined by RFC 7638.

    The thumbprint is the digest itself: the hash octets of the canonical JSON form of the key. base64Url is its textual form (unpadded base64url), which is the value conventionally used as a JWT/JWK kid. uri is the RFC 9278 URI form.

    Only SHA-256 is supported at the moment. RFC 7638 permits other hash functions.

  24.  case class JwtSession(headerData: JsObject, claimData: JsObject, signature: String)(implicit conf: Configuration, clock: Clock) extends Product with Serializable

    Similar to the default Play Session but using JsObject instead of Map[String, String].

    Similar to the default Play Session but using JsObject instead of Map[String, String]. The data is separated into two attributes: headerData and claimData. There is also a optional signature. Most of the time, you should only care about the claimData which stores the claim of the token containing the custom values you eventually put in it. That's why all methods of JwtSession (such as add and removing values) only modifiy the claimData.

    To see a full list of samples, check the online documentation.

    Warning Be aware that if you override the claimData (using withClaim for example), you might override some attributes that were automatically put inside the claim such as the expiration of the token.

  30.  sealed trait OkpCurve extends AnyRef

    A curve usable in an OKP JWK (RFC 8037 section 2).

    A curve usable in an OKP JWK (RFC 8037 section 2).

    Ed25519 and Ed448 are supported. Turning a key on these curves into a JDK PublicKey, and verifying signatures with it, requires a JDK that provides the EdDSA KeyFactory (JDK 15+). The other OKP curves, such as X25519 and X448, are not supported.

  31.  final class OkpJwk extends Jwk

    An OKP JWK (RFC 8037) holding an Ed25519 or Ed448 public key.

    An OKP JWK (RFC 8037) holding an Ed25519 or Ed448 public key.

    Building the publicKey of such a key requires a JDK that provides the EdDSA KeyFactory, which is the case from JDK 15 on. See OkpCurve.

    Exceptions thrown

    JwtValidationException if x does not decode to curve.keyLength bytes

    java.lang.IllegalArgumentException if x is not valid base64url

  7.  object Jwt extends Jwt

    Test implementation of JwtCore using only Strings.

    Test implementation of JwtCore using only Strings. Most of the time, you should use a lib implementing JSON and shouldn't be using this object. But just in case you need pure Scala support, here it is.

    To see a full list of samples, check the online documentation.

    Warning: since there is no JSON support in Scala, this object doesn't have any way to parse a JSON string as an AST, so it only uses regex with all the limitations it implies. Try not to use keys like exp and nbf in sub-objects of the claim. For example, if you try to use the following claim: {"user":{"exp":1},"exp":1300819380}, it should be correct but it will fail because the regex extracting the expiration will return 1 instead of 1300819380. Sorry about that.
